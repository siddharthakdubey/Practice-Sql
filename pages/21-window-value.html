Window value functions

LAG, LEAD, FIRST_VALUE and LAST_VALUE: read a value from another row of the same window, without a self-join.

After this topic you will compare a row with the previous or next row (period-over-period change, gaps between events), fetch the first or last value of a group, and avoid the LAST_VALUE frame trap.

LAG and LEAD

LAG (expression [, offset [, default]]) OVER ([PARTITION BY ...] ORDER BY ...)   -- value from an EARLIER row
LEAD(expression [, offset [, default]]) OVER ([PARTITION BY ...] ORDER BY ...)   -- value from a LATER row
  • offset: how many rows back/forward (default 1).
  • default: returned when there is no such row (default NULL). So LAG(Sales, 1, 0) gives 0 for the first row.
  • ORDER BY is required: "previous" only makes sense in a defined order.
SELECT OrderID, Sales,
       LAG (Sales) OVER (ORDER BY OrderDate, OrderID) AS PrevSales,
       LEAD(Sales) OVER (ORDER BY OrderDate, OrderID) AS NextSales,
       Sales - LAG(Sales) OVER (ORDER BY OrderDate, OrderID) AS ChangeVsPrev
FROM Orders;

Period-over-period analysis (month on month)

WITH monthly AS (
    SELECT DATETRUNC(MONTH, OrderDate) AS Mth, SUM(Sales) AS Total      -- or: EOMONTH(OrderDate) / YEAR+MONTH
    FROM Orders GROUP BY DATETRUNC(MONTH, OrderDate)
)
SELECT Mth, Total,
       LAG(Total) OVER (ORDER BY Mth)                                   AS PrevMonth,
       Total - LAG(Total) OVER (ORDER BY Mth)                           AS Change,
       ROUND(100.0 * (Total - LAG(Total) OVER (ORDER BY Mth))
             / NULLIF(LAG(Total) OVER (ORDER BY Mth), 0), 2)            AS PctChange
FROM monthly;
Mth | Total | PrevMonth | Change | PctChange 2025-01-01 | 180 | NULL | NULL | NULL 2025-02-01 | 105 | 180 | -75 | -41.67 2025-03-01 | 115 | 105 | 10 | 9.52

Notice the pattern: aggregate first in a CTE, then window over the aggregated rows. NULLIF avoids division by zero. (Year-over-year: LAG(Total, 12) over monthly rows with no missing months.)

Time between events (retention, customer behaviour)

SELECT OrderID, CustomerID, OrderDate,
       DATEDIFF(DAY,
                LAG(OrderDate) OVER (PARTITION BY CustomerID ORDER BY OrderDate),
                OrderDate) AS DaysSincePrevOrder
FROM Orders WHERE CustomerID = 2;
OrderID | CustomerID | OrderDate | DaysSincePrevOrder 1001 | 2 | 2025-01-01 | NULL 1006 | 2 | 2025-02-05 | 35 1009 | 2 | 2025-03-10 | 33

PARTITION BY restarts per customer, so the first order of each customer has no previous (NULL). Average of this column = average repurchase gap. A bank analogue: days between a customer's transactions, or detecting two logins from different cities within minutes.

FIRST_VALUE and LAST_VALUE

SELECT FirstName, Department, Salary,
       FIRST_VALUE(FirstName) OVER (PARTITION BY Department ORDER BY Salary DESC) AS TopEarner,
       FIRST_VALUE(Salary)    OVER (PARTITION BY Department ORDER BY Salary DESC) - Salary AS BehindTop
FROM Employees;
FirstName | Department | Salary | TopEarner | BehindTop Kevin | Marketing | 65000 | Kevin | 0 Frank | Marketing | 55000 | Kevin | 10000 Michael | Sales | 90000 | Michael | 0 Mary | Sales | 75000 | Michael | 15000 Carol | Sales | 55000 | Michael | 35000

The LAST_VALUE trap

With an ORDER BY and no frame, the default frame ends at the current row, so "last value" is just the current row's own value:

SELECT OrderID, Sales,
       LAST_VALUE(Sales) OVER (ORDER BY OrderDate)                               AS Wrong,
       LAST_VALUE(Sales) OVER (ORDER BY OrderDate
             ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING)           AS Right
FROM Orders WHERE CustomerID = 3;
OrderID | Sales | Wrong | Right 1002 | 60 | 60 | 40 1007 | 40 | 40 | 40
FixEither extend the frame to UNBOUNDED FOLLOWING (above), or flip the ORDER BY and use FIRST_VALUE: FIRST_VALUE(Sales) OVER (ORDER BY OrderDate DESC). The second is shorter and avoids the trap. (FIRST_VALUE's default frame starts at the beginning, so it works as expected.)

NTH_VALUE exists in PostgreSQL, Oracle and MySQL but not in SQL Server. Emulate "2nd highest" with ROW_NUMBER() / DENSE_RANK() (topic 20).

RESPECT / IGNORE NULLS

By default LAG/LEAD/FIRST_VALUE return NULL if the neighbour value is NULL. IGNORE NULLS skips them (carry the last known value forward). It is available in SQL Server 2022 and Oracle; on older SQL Server use a "latest non-null" workaround with MAX(...) OVER (... ROWS UNBOUNDED PRECEDING) on a group id.
