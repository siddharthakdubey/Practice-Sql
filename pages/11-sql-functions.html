SQL functions (overview)

A function takes values in and gives a value back. This topic is the map for the next ten.

After this topic you will tell single-row, aggregate and window functions apart, nest functions, and know which family to reach for.

Two main kinds: row-level and multi-row

Single-row (scalar) functionsMulti-row functions
InputOne row's value(s)Many rows
OutputOne value per input rowAggregate: one value per group (rows collapse). Window: one value per row and rows stay.
ExamplesUPPER, ROUND, DATEADD, ISNULL, CASEAggregate: SUM, COUNT, AVG. Window: SUM() OVER, RANK, LAG
Topics12 string, 13 numeric, 14 date/time, 15 NULL, 16 CASE17 aggregate, 18-21 window

Single-row function: rows in = rows out

SELECT FirstName, UPPER(FirstName) AS Shout FROM Customers;

Aggregate function: many rows in, one row out

SELECT SUM(Score) AS TotalScore FROM Customers;

(A window function, topic 18, is the third option: it computes across rows but keeps every row.)

Nesting: functions inside functions

Run from the innermost outwards, like brackets in maths.

SELECT UPPER(LEFT(TRIM('  kevin brown '), 5));
--      4          3     2          1
-- 1) TRIM  -> 'kevin brown'
-- 2) LEFT 5 -> 'kevin'
-- 3) UPPER -> 'KEVIN'

Functions on columns can kill index use ("non-sargable")WHERE YEAR(OrderDate) = 2025 forces the engine to compute YEAR() for every row, so an index on OrderDate cannot be used. Rewrite as WHERE OrderDate >= '2025-01-01' AND OrderDate < '2026-01-01'. Details in topics 30 and 33.

Type conversion (used everywhere)

SELECT CAST('123' AS INT) + 1;                 -- 124   (ANSI standard)
SELECT CONVERT(VARCHAR(10), GETDATE(), 23);    -- '2026-11-01'  (T-SQL, style 23 = yyyy-mm-dd)
SELECT TRY_CAST('abc' AS INT);                 -- NULL instead of an error: great for dirty data
SELECT 10 / 4;                                 -- 2   (integer division!)
SELECT 10 / 4.0;                               -- 2.500000
Implicit conversionSQL Server converts types silently when they differ ('1' + 1 = 2). That is convenient but slow on join/filter columns and a source of subtle bugs. Match types explicitly.
Try it

Classify each function as single-row, aggregate or window: LEN, AVG, RANK() OVER (...), DATEADD, COUNT. Then run SELECT 10 / 4, 10 / 4.0, CAST(10 AS DECIMAL(5,2)) / 4; and explain the three answers.
