Common Table Expressions (CTE)

Name a subquery with WITH, read your SQL top to bottom, chain steps, and walk hierarchies with recursion.

After this topic you will write single and chained CTEs, use a CTE to filter window results, build recursive CTEs (counters, date series, org charts), and know the limits of a CTE.

Syntax

WITH cte_name (optional, column, list) AS (
    SELECT ...                      -- any SELECT
)
SELECT * FROM cte_name;             -- the main query using it
  • A CTE is a named, temporary result set that exists only for the one statement that follows (SELECT, INSERT, UPDATE, DELETE or MERGE).
  • Nothing is stored. It is like giving a derived table (topic 23) a name and putting it above the main query.
  • If a statement before WITH is on the same batch, end it with ; (SQL Server demands it).
WITH customer_totals AS (
    SELECT CustomerID, SUM(Sales) AS Total, COUNT(*) AS Orders
    FROM Orders
    GROUP BY CustomerID
)
SELECT c.FirstName, t.Total, t.Orders
FROM customer_totals t
JOIN Customers c ON c.CustomerID = t.CustomerID
WHERE t.Total > 60
ORDER BY t.Total DESC;
FirstName | Total | Orders Mary | 100 | 2 Mark | 85 | 2 Kevin | 65 | 3

Chained CTEs: one builds on the previous

WITH delivered AS (
    SELECT CustomerID, Sales FROM Orders WHERE OrderStatus = 'Delivered'
),
per_customer AS (
    SELECT CustomerID, SUM(Sales) AS Total FROM delivered GROUP BY CustomerID   -- uses the CTE above
),
avg_all AS (
    SELECT AVG(Total) AS AvgTotal FROM per_customer
)
SELECT p.CustomerID, p.Total, a.AvgTotal
FROM per_customer p CROSS JOIN avg_all a        -- avg_all has one row: crossing it is safe
WHERE p.Total > a.AvgTotal;
CustomerID | Total | AvgTotal 4 | 85 | 63.333333
  • Separate CTEs with commas; WITH is written once.
  • A CTE can use earlier CTEs, never later ones.
  • The same CTE can be referenced several times (self-join, two uses).

CTE vs subquery vs view: why bother?

  • Readability: steps named and ordered top to bottom instead of nested inside-out.
  • Reuse inside one statement: write once, refer many times.
  • Filtering on window functions (topic 18, 20) and on aggregates of aggregates.
  • Recursion: only a CTE can reference itself.
Performance honestyIn SQL Server a non-recursive CTE is inlined, like a subquery: it is not saved or cached, and if you reference it twice it may be computed twice. It does not make a query faster. If the same heavy intermediate result is used many times, a temp table can be better (topic 26, 27).

CTE for data changes

WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY CustomerID, ProductID ORDER BY OrderID) AS rn FROM Orders
)
DELETE FROM ranked WHERE rn > 1;                -- removes duplicates, keeps the first of each pair

Recursive CTE: a query that calls itself

Two parts joined by UNION ALL: the anchor (starting rows) and the recursive member (reads the rows produced in the previous round). It stops when a round produces no new rows.

Example 1: count 1 to 5

WITH numbers AS (
    SELECT 1 AS n                         -- anchor: start
    UNION ALL
    SELECT n + 1 FROM numbers WHERE n < 5   -- recursive member + stopping condition
)
SELECT n FROM numbers;                    -- 1, 2, 3, 4, 5

Example 2: a calendar of dates (fills gaps in reports)

WITH days AS (
    SELECT CAST('2025-03-01' AS DATE) AS d
    UNION ALL
    SELECT DATEADD(DAY, 1, d) FROM days WHERE d < '2025-03-31'
)
SELECT d FROM days OPTION (MAXRECURSION 400);   -- default limit is 100 rounds; 0 = unlimited (careful!)

Example 3: the org chart (hierarchy walk)

WITH org AS (
    SELECT EmployeeID, FirstName, ManagerID, 0 AS Level,
           CAST(FirstName AS VARCHAR(200)) AS Path
    FROM Employees WHERE ManagerID IS NULL                       -- anchor: the top boss

    UNION ALL

    SELECT e.EmployeeID, e.FirstName, e.ManagerID, o.Level + 1,
           CAST(o.Path + ' > ' + e.FirstName AS VARCHAR(200))
    FROM Employees e
    JOIN org o ON e.ManagerID = o.EmployeeID                     -- employees whose manager was found last round
)
SELECT Level, REPLICATE('   ', Level) + FirstName AS Person, Path FROM org ORDER BY Path;
Level | Person | Path 0 | Frank | Frank 1 |   Kevin | Frank > Kevin 2 |     Michael | Frank > Kevin > Michael 1 |   Mary | Frank > Mary 2 |     Carol | Frank > Mary > Carol
Always have a stopping conditionIf the data contains a cycle (A manages B manages A) or you forget the WHERE n < 5, the recursion never ends; SQL Server stops it at 100 rounds with an error (MAXRECURSION). Column types in anchor and recursive parts must match exactly (hence the CAST to VARCHAR(200)).

Uses: org charts, product category trees, bill of materials, folder trees, network paths, generating number and date series.

Rules

  • No ORDER BY inside a CTE (unless TOP); order in the main query.
  • CTE column names must be unique (alias expressions).
  • The CTE name hides a real table of the same name inside the statement. Pick unique names.
  • Recursive CTEs: anchor first, UNION ALL only, recursive reference exactly once, no aggregates or TOP in the recursive part.
