Subqueries

A query inside another query. Learn the kinds, where they can sit, and how the correlated kind really runs.

After this topic you will write scalar, multi-row, table and correlated subqueries, choose between IN, EXISTS and JOIN, use ANY/ALL, and avoid the NOT IN NULL trap.

What is a subquery?

A SELECT in parentheses used as a value, a list, or a table inside another statement (the outer query). The inner query runs first (conceptually), and its result feeds the outer one.

Scalarone row, one column (a single value)anywhere an expression fits: SELECT, WHERE, HAVING
Multi-row (list)one column, many rowswith IN, ANY, ALL, EXISTS

1. Scalar subquery

SELECT OrderID, Sales
FROM Orders
WHERE Sales > (SELECT AVG(Sales) FROM Orders);      -- inner returns one number: 40
OrderID | Sales 1002 | 60 1004 | 90 1008 | 50 1010 | 45

If a scalar subquery returns more than one row, you get an error; if it returns none, it yields NULL. Also usable in SELECT:

SELECT FirstName,
       (SELECT COUNT(*) FROM Orders o WHERE o.CustomerID = c.CustomerID) AS OrderCount     -- correlated
FROM Customers c;
FirstName | OrderCount Jossef | 2 Kevin | 3 Mary | 2 Mark | 2 Anna | 0

2. Multi-row subquery: IN

SELECT FirstName FROM Customers
WHERE CustomerID IN (SELECT CustomerID FROM Orders WHERE OrderStatus = 'Delivered');
-- inner returns the list (2, 1, 4, 2, 1, 4): result Jossef, Kevin, Mark

ANY / ALL compare with a whole list:

SELECT OrderID, Sales FROM Orders
WHERE Sales > ALL (SELECT Sales FROM Orders WHERE CustomerID = 2);   -- bigger than EVERY order of customer 2 (max 25)
-- ANY: bigger than at least one (= bigger than the minimum 20); "= ANY" is the same as IN

3. Derived table: subquery in FROM

Treat a query result as a temporary table. It must have an alias, and every column needs a name.

SELECT c.FirstName, t.Total
FROM Customers c
JOIN (SELECT CustomerID, SUM(Sales) AS Total FROM Orders GROUP BY CustomerID) AS t
     ON t.CustomerID = c.CustomerID
WHERE t.Total > 60;
FirstName | Total Kevin | 65 Mary | 100 Mark | 85

This is the "aggregate first, then join" fix for the fan-out problem (topic 17). It is also the way to filter on a window function result (topic 18). A CTE does the same with better readability (topic 24).

4. Correlated subquery: runs once per outer row

The inner query refers to a column of the outer query, so it cannot run on its own; it is re-evaluated for each outer row (the optimizer often rewrites it into a join, but think of it as a loop).

-- orders bigger than the average of THEIR OWN customer's orders
SELECT o.OrderID, o.CustomerID, o.Sales
FROM Orders o
WHERE o.Sales > (SELECT AVG(o2.Sales)
                 FROM Orders o2
                 WHERE o2.CustomerID = o.CustomerID);     -- o.CustomerID comes from the outer row

5. EXISTS: "is there at least one?"

SELECT FirstName FROM Customers c
WHERE EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerID = c.CustomerID);          -- Jossef, Kevin, Mary, Mark

SELECT FirstName FROM Customers c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerID = c.CustomerID);      -- Anna
  • EXISTS returns TRUE/FALSE and stops at the first match. What the inner SELECT lists does not matter (SELECT 1 is the convention).
  • Unlike a JOIN it never multiplies rows: Kevin appears once, not three times.

The NOT IN trap (NULL)

SELECT FirstName FROM Customers
WHERE CustomerID NOT IN (SELECT CustomerID FROM Orders);                    -- Anna: fine today
-- but if Orders.CustomerID ever contains a NULL:
SELECT FirstName FROM Customers
WHERE CustomerID NOT IN (SELECT CustomerID FROM Orders UNION ALL SELECT NULL);   -- returns NO ROWS
Whyx NOT IN (2, 3, NULL) means x<>2 AND x<>3 AND x<>NULL; the last part is UNKNOWN, so the whole thing can never be TRUE. Prefer NOT EXISTS (or a LEFT JOIN ... IS NULL anti join) for "not in". Safe patch if you must: NOT IN (SELECT CustomerID FROM Orders WHERE CustomerID IS NOT NULL).

Modern optimizers often produce the same plan for IN, EXISTS and an inner JOIN; choose for clarity and correctness, then check the plan (topic 31).

Other rules

  • A subquery cannot have ORDER BY unless it also has TOP/OFFSET (the order is meaningless inside).
  • Subqueries can nest, but past two levels CTEs are far easier to read.
  • A subquery in the SELECT list that is correlated runs for every row: fine for hundreds, slow for millions. Use a join + group by instead.
