AI and SQL

AI can draft, explain and review SQL quickly. It can also be confidently wrong. Use it as a fast junior colleague whose work you always verify.

After this topic you will prompt an AI assistant for SQL with the right context, verify what it returns with a repeatable routine, recognise its typical mistakes, and know the safety rules for letting AI near real data.

Give it the context it cannot guess

An AI does not know your database. It will invent plausible column names if you do not supply them. A good prompt has five parts:

  1. Dialect and version: "SQL Server 2022 T-SQL".
  2. Schema: paste the CREATE TABLE statements (with keys and types), or at least table and column names with relationships. Add a few sample rows.
  3. The business question in plain words, including the grain: "one row per customer".
  4. Rules and edge cases: "include customers without orders", "ignore cancelled orders", "NULL score counts as 0".
  5. Output format: column names and order, "return only the query, then explain assumptions".
You are a senior SQL Server developer.
Dialect: T-SQL (SQL Server 2022).
Schema:
  Customers(CustomerID PK, FirstName, LastName NULL, Country, Score NULL)
  Orders(OrderID PK, CustomerID NULL (no FK), ProductID FK, OrderDate, OrderStatus, Quantity, Sales)
Task: total Sales per customer over all orders, including customers with no orders (show 0).
Output columns: CustomerID, FirstName, TotalSales. Sort by TotalSales descending.
List any assumptions you made and any edge cases I should test.
Ask it to ask youAdd "If anything is ambiguous, ask me before writing the query." This avoids confident guesses.

Use AI to teach you, not just to type

  • Write your own answer first, then paste both and ask: "Compare my query with yours: correctness, edge cases, readability, performance."
  • Ask for "three different ways" (join, subquery, window) and the trade-offs; run all and compare plans.
  • Ask it to break your query: "Give me data that makes this query return a wrong answer."
  • Ask for explain-like-I-know-banking analogies, but verify claims about engine internals.

Safety rules (important)

Data and access
  • Never paste real customer, account or employee data into a public AI tool. Use schemas, fake samples, or masked data. Follow your bank's policy; many ban external AI tools outright.
  • Prefer schema-only prompts: tables and column names are usually enough.
  • If an application lets AI run SQL: use a read-only login limited to a safe schema or views, a row limit and timeout, allow-list statements (SELECT only, no semicolon chains), log every generated query, and show it to a person before running anything important.
  • AI suggests, a person confirms. It must not write money, attendance or customer records on its own.

A habit that scales

  1. Understand the question and the grain yourself first.
  2. Let AI draft or review.
  3. Run on small data where you can predict the answer (our 10-row Orders table is perfect for this).
  4. Check row counts, totals, NULLs and edge cases.
  5. Check the plan on realistic volume.
  6. Commit it (with a comment on why) to your Git repository, as you will do with the 120 practice questions.
