NULL functions

NULL means "unknown". It spreads through calculations and quietly changes your totals, so learn the tools that tame it.

After this topic you will detect NULL, replace it with ISNULL and COALESCE, create NULL on purpose with NULLIF, and predict how NULL behaves in maths, aggregates, sorting, joins and constraints.

What NULL is (and is not)

ValueMeaning
NULLno value / unknown / not applicable
0a real number zero
'' (empty string)a real, known text of length 0
' ' (spaces)a real text of spaces

Anna's Score is NULL: we do not know it. It is not a score of 0.

NULL spreads

SELECT 5 + NULL            -- NULL
     , 'abc' + NULL        -- NULL
     , NULL = NULL         -- not true (UNKNOWN)
     , NULL IS NULL        -- true
     , LEN(NULL)           -- NULL
;

Anything combined with NULL by arithmetic or comparison becomes NULL / UNKNOWN. Use IS NULL / IS NOT NULL to test (topic 7).

ISNULL(x, replacement) and COALESCE(a, b, c, ...)

SELECT FirstName,
       ISNULL(LastName, 'n/a')                 AS Last1,      -- T-SQL only, exactly 2 arguments
       COALESCE(LastName, FirstName, 'n/a')    AS Last2,      -- ANSI, any number: first non-NULL wins
       ISNULL(Score, 0)                        AS ScoreOrZero
FROM Customers;

NULL in aggregates: the silent total-changer

Aggregates (SUM, AVG, MIN, MAX, COUNT(column)) ignore NULL. COUNT(*) counts rows regardless.

SELECT COUNT(*)                AS Rows,          -- 5
       COUNT(Score)            AS WithScore,     -- 4
       SUM(Score)              AS Total,         -- 2500
       AVG(Score)              AS AvgIgnoringNull,     -- 625   = 2500 / 4
       AVG(ISNULL(Score, 0))   AS AvgNullAsZero        -- 500   = 2500 / 5
FROM Customers;
Decide deliberatelyIs a missing value "unknown, leave it out" or "really zero"? An unpaid invoice with no payment date is a different story from a payment of 0. There is no universal answer; the business meaning decides.

NULLIF(a, b): turn a value INTO NULL

Returns NULL if a equals b, otherwise returns a. The classic use is to prevent a divide-by-zero error: dividing by NULL gives NULL, not an error.

SELECT 100 / NULLIF(0, 0);                    -- NULL, instead of "Divide by zero error"
SELECT Sales / NULLIF(Quantity, 0) AS PricePerUnit FROM Orders;

-- turn placeholder strings into proper NULLs
SELECT NULLIF(LastName, '') FROM Customers;   -- '' becomes NULL

Safe patterns

-- Safe ratio, with default 0 when it cannot be calculated
SELECT ISNULL(Sales / NULLIF(Quantity, 0), 0) FROM Orders;

-- Full name without a stray space or NULL
SELECT COALESCE(FirstName + ' ' + LastName, FirstName) FROM Customers;   -- Mary: 'Mary'

-- Sort NULLs last (SQL Server puts NULL first in ASC)
SELECT FirstName, Score FROM Customers
ORDER BY CASE WHEN Score IS NULL THEN 1 ELSE 0 END, Score;

-- Compare two columns where NULL counts as "equal to NULL"
WHERE a = b OR (a IS NULL AND b IS NULL)

NULL in joins and constraints

  • A NULL join key never matches anything, not even another NULL. Those rows disappear from INNER JOINs (topic 8).
  • NOT IN with a NULL in the list returns nothing (topic 7, 23).
  • A PRIMARY KEY column can never be NULL; a UNIQUE column allows only one NULL in SQL Server (other databases allow many).
  • A CHECK constraint passes when its condition is UNKNOWN, so NULL slips through CHECK (Age > 0). Add NOT NULL if the value is required.
  • GROUP BY and DISTINCT treat all NULLs as one group.

Find the dirty data

-- how many NULL/blank values per column (a data-quality check)
SELECT SUM(CASE WHEN LastName IS NULL THEN 1 ELSE 0 END) AS NullLast,
       SUM(CASE WHEN Score    IS NULL THEN 1 ELSE 0 END) AS NullScore
FROM Customers;                                   -- 1, 1
