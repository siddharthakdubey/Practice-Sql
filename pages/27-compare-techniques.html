Compare advanced techniques

Subquery, CTE, view, temp table, table variable and CTAS table: same goal, different trade-offs. Learn to pick.

After this topic you will solve one question six ways, compare scope, storage and speed, and use a simple decision guide for real work.

One question, six solutions

"Customers whose total sales exceed 60, with their names." Expected: Kevin 65, Mary 100, Mark 85.

1. Subquery (derived table)

SELECT c.FirstName, t.Total
FROM Customers c
JOIN (SELECT CustomerID, SUM(Sales) AS Total FROM Orders GROUP BY CustomerID) t ON t.CustomerID = c.CustomerID
WHERE t.Total > 60;

2. CTE

WITH t AS (SELECT CustomerID, SUM(Sales) AS Total FROM Orders GROUP BY CustomerID)
SELECT c.FirstName, t.Total FROM Customers c JOIN t ON t.CustomerID = c.CustomerID WHERE t.Total > 60;

3. View

CREATE VIEW dbo.v_CustomerTotals AS SELECT CustomerID, SUM(Sales) AS Total FROM dbo.Orders GROUP BY CustomerID;
GO
SELECT c.FirstName, t.Total FROM Customers c JOIN dbo.v_CustomerTotals t ON t.CustomerID = c.CustomerID WHERE t.Total > 60;

4. Temp table

SELECT CustomerID, SUM(Sales) AS Total INTO #t FROM Orders GROUP BY CustomerID;
SELECT c.FirstName, t.Total FROM Customers c JOIN #t t ON t.CustomerID = c.CustomerID WHERE t.Total > 60;

5. Table variable

DECLARE @t TABLE (CustomerID INT, Total DECIMAL(10,2));
INSERT INTO @t SELECT CustomerID, SUM(Sales) FROM Orders GROUP BY CustomerID;
SELECT c.FirstName, t.Total FROM Customers c JOIN @t t ON t.CustomerID = c.CustomerID WHERE t.Total > 60;

6. CTAS (permanent table)

SELECT CustomerID, SUM(Sales) AS Total INTO dbo.CustomerTotals_Snapshot FROM Orders GROUP BY CustomerID;
SELECT c.FirstName, t.Total FROM Customers c JOIN dbo.CustomerTotals_Snapshot t ON t.CustomerID = c.CustomerID WHERE t.Total > 60;

Rules of thumb

  1. Start with a CTE. If it is fast enough, stop.
  2. If the plan is slow and the same intermediate result is used more than once, or has hundreds of thousands of rows, materialise it in a #temp table and index it. Measure before and after.
  3. If other people or tools need the logic, make it a view.
  4. Do not stack views on views; flatten into one or the optimizer drowns.
  5. A snapshot is only as good as its refresh schedule. Name it with its date or load process.
  6. Whatever you choose, check the execution plan (topic 31) rather than guessing. CTE vs subquery is usually identical to the engine.

Common interview questions

Is a CTE faster than a subquery?

Usually no: in SQL Server a CTE is expanded like a subquery. It is a readability tool. Faster results come from indexes, set-based logic and sometimes temp tables.

Temp table or table variable?

Temp table for large or reused sets (statistics, indexes). Table variable for small sets, in procedures with many executions where recompiles hurt. Neither "lives in memory only": both use tempdb.

View or stored procedure?

View when the result should behave like a table (be joined, filtered by the caller). Procedure when you need parameters, multiple statements, transactions, or side effects (topic 28). A view cannot take parameters; an inline table-valued function can.

Can a view be slower than the raw query?

Not by itself, but wide views joined with many tables get selected by queries needing only two columns, and the engine may still do all joins unless it can prove they are unnecessary. Create narrower views for narrower needs.
