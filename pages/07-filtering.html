Filtering data

Everything you can put in a WHERE clause: comparisons, AND/OR/NOT, BETWEEN, IN, LIKE, and the NULL trap.

After this topic you will filter with every common operator, predict how AND/OR precedence changes results, search text with wildcards, and handle NULL correctly (three-valued logic).

SELECT FirstName, Score FROM Customers WHERE Score >= 500;
FirstName | Score Kevin | 900 Mary | 750 Mark | 500

Jossef (350) fails the test. Anna (NULL) also is not returned: NULL >= 500 is not true. Keep that in mind.

Combining conditions: AND, OR, NOT

  • A AND B: both must be true. A OR B: at least one. NOT A: reverses.
  • Precedence: NOT first, then AND, then OR. Use parentheses to be explicit.
SELECT FirstName, Country, Score FROM Customers
WHERE Country = 'Germany' OR Country = 'USA' AND Score > 800;
-- is read as:  Germany  OR  (USA AND Score > 800)
Mixed AND/OR without bracketsis the most common filtering bug. (Country='Germany' OR Country='USA') AND Score > 800 returns only Kevin: a different answer.

BETWEEN, IN

WHERE Score BETWEEN 500 AND 800          -- same as Score >= 500 AND Score <= 800 (both ends INCLUDED)
WHERE Country IN ('Germany', 'India')    -- same as Country = 'Germany' OR Country = 'India'
WHERE Country NOT IN ('USA')
FirstName | Score Mary | 750 Mark | 500
BETWEEN with datesOrderDate BETWEEN '2025-01-01' AND '2025-01-31' is fine for a DATE column, but with DATETIME it misses everything after midnight on the 31st. Prefer >= '2025-01-01' AND < '2025-02-01' (topic 14).

LIKE: pattern matching on text

WildcardMatches
%any number of characters (including none)
_exactly one character
[abc] / [a-c] / [^a](T-SQL) one character from / in range / not in the set
WHERE FirstName LIKE 'M%'        -- starts with M      : Mary, Mark
WHERE FirstName LIKE '%n'        -- ends with n        : Kevin
WHERE FirstName LIKE '%ar%'      -- contains "ar"      : Mary, Mark
WHERE FirstName LIKE '__r_'      -- 4 chars, 3rd is r  : Mary, Mark
WHERE FirstName LIKE '[JK]%'     -- starts with J or K : Jossef, Kevin
PerformanceLIKE 'M%' can use an index on the column. LIKE '%ar%' (leading wildcard) cannot, so it scans every row. Matching is case-insensitive by default in SQL Server (depends on collation).

NULL: unknown, not zero

NULL means "value unknown". Any comparison with NULL gives UNKNOWN, and WHERE keeps only rows that are TRUE.

ExpressionResult
NULL = NULLUNKNOWN (not true!)
NULL <> 5UNKNOWN
NULL IS NULLTRUE
TRUE AND UNKNOWNUNKNOWN
TRUE OR UNKNOWNTRUE
NOT UNKNOWNUNKNOWN
SELECT FirstName FROM Customers WHERE Score = NULL;       -- returns nothing. Wrong!
SELECT FirstName FROM Customers WHERE Score IS NULL;      -- Anna
SELECT FirstName FROM Customers WHERE Score IS NOT NULL;  -- the other four

-- "everyone NOT from Germany, including people with unknown country":
WHERE Country <> 'Germany' OR Country IS NULL
The NOT IN trapx NOT IN (1, 2, NULL) is never true: it expands to x<>1 AND x<>2 AND x<>NULL, and the last part is UNKNOWN. If a subquery behind NOT IN returns a NULL, you get zero rows. Use NOT EXISTS instead (topic 23).

Filtering patterns worth remembering

WHERE OrderDate >= '2025-02-01' AND OrderDate < '2025-03-01'   -- a month, safe for any date type
WHERE ShipDate IS NULL                                            -- not shipped yet
WHERE Sales > (SELECT AVG(Sales) FROM Orders)                    -- subquery (topic 23)
