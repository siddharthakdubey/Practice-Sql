String functions

Clean, cut, join and search text. Most real-world SQL starts with messy strings.

After this topic you will manipulate text with CONCAT, UPPER/LOWER, TRIM, REPLACE, LEN, LEFT/RIGHT/SUBSTRING, CHARINDEX, STRING_AGG and STRING_SPLIT, and combine them to parse values.

Join text: CONCAT and +

SELECT FirstName, LastName,
       FirstName + ' ' + LastName        AS WithPlus,
       CONCAT(FirstName, ' ', LastName)  AS WithConcat,
       CONCAT_WS(' ', FirstName, LastName) AS WithSeparator
FROM Customers;
FirstName | LastName | WithPlus | WithConcat | WithSeparator Jossef | Goldberg | Jossef Goldberg | Jossef Goldberg | Jossef Goldberg Kevin | Brown | Kevin Brown | Kevin Brown | Kevin Brown Mary | NULL | NULL | Mary  | Mary Mark | Schwarz | Mark Schwarz | Mark Schwarz | Mark Schwarz Anna | Adams | Anna Adams | Anna Adams | Anna Adams
NULL poisons +'Mary' + NULL is NULL, but CONCAT treats NULL as an empty string (leaving a trailing space for Mary). CONCAT_WS (with separator) skips NULLs entirely, so it is the cleanest for names and addresses.

Case and whitespace

SELECT UPPER('Kevin')            -- KEVIN
     , LOWER('Kevin')            -- kevin
     , TRIM('   Kevin  ')        -- 'Kevin'   (both ends; LTRIM / RTRIM for one side)
     , REPLACE('a-b-c', '-', '') -- 'abc'     (remove or swap text)
     , REPLACE(Country, 'USA', 'United States')
FROM Customers;

Typical use: compare cleanly. WHERE LOWER(TRIM(Email)) = 'a@b.com' (note the index warning from topic 11).

Length

SELECT LEN('Kevin')            -- 5   (ignores trailing spaces: LEN('Kevin  ') is also 5)
     , DATALENGTH('Kevin')     -- 5 bytes (NVARCHAR doubles it)
     , LEN(LastName)           -- NULL for Mary: function of NULL is NULL
FROM Customers;

Use length to find bad data: WHERE LEN(Phone) <> 10.

Cut: LEFT, RIGHT, SUBSTRING

SELECT LEFT('Goldberg', 4)         -- 'Gold'     first 4 characters
     , RIGHT('Goldberg', 4)        -- 'berg'     last 4
     , SUBSTRING('Goldberg', 5, 3) -- 'ber'      start at position 5 (positions start at 1!), take 3
     , SUBSTRING('Goldberg', 5, LEN('Goldberg'))  -- 'berg'  "to the end" idiom
;
Position | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 Letter | G | o | l | d | b | e | r | g

Find: CHARINDEX

SELECT CHARINDEX('@', 'jo@bank.in');         -- 3   (position of the first match, 0 if not found)
SELECT CHARINDEX('x', 'jo@bank.in');         -- 0
SELECT CHARINDEX('.', 'a.b.c', 3);           -- 4   (start searching at position 3)

Combine FIND with CUT to parse text. Extract the domain of an e-mail:

DECLARE @email VARCHAR(50) = 'jo@bank.in';

SELECT SUBSTRING(@email, CHARINDEX('@', @email) + 1, LEN(@email)) AS Domain;   -- 'bank.in'
SELECT LEFT(@email, CHARINDEX('@', @email) - 1)                   AS UserName; -- 'jo'

Rows to one string, and one string to rows

-- STRING_AGG: many rows -> one string (it is an aggregate, topic 17)
SELECT Country, STRING_AGG(FirstName, ', ') WITHIN GROUP (ORDER BY FirstName) AS People
FROM Customers
GROUP BY Country;
Country | People Germany | Jossef, Mark USA | Anna, Kevin, Mary 
-- STRING_SPLIT: one string -> many rows (SQL Server 2016+)
SELECT value FROM STRING_SPLIT('red,green,blue', ',');
value red green blue

A worked clean-up

-- Standardise names: trim, Proper case for first letter, treat NULL
SELECT CustomerID,
       UPPER(LEFT(TRIM(FirstName), 1)) + LOWER(SUBSTRING(TRIM(FirstName), 2, LEN(FirstName))) AS CleanFirst,
       ISNULL(LastName, 'n/a') AS Last
FROM Customers;

Pitfalls

  • Positions start at 1, not 0.
  • LEN ignores trailing spaces; leading spaces count.
  • Comparisons are case-insensitive by default (collation), unlike many languages.
  • A string function given NULL returns NULL (except CONCAT, ISNULL).
  • Using functions on a filtered column prevents index use.
