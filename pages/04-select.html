Query data (SELECT)

The most used statement in SQL. Learn each clause, then the order the engine really runs them.

After this topic you will write SELECT with FROM, WHERE, GROUP BY, HAVING, ORDER BY, DISTINCT, TOP and OFFSET-FETCH, use aliases and static values, and explain the logical processing order.

Data used:

1. SELECT and FROM

SELECT * FROM Customers;                          -- every column, every row
SELECT FirstName, Country FROM Customers;         -- only chosen columns
FirstName | Country Jossef | Germany Kevin | USA Mary | USA Mark | Germany Anna | USA
Avoid SELECT * in real codeIt reads columns you do not need (slower, more network), and it breaks when someone adds a column. Use * for quick exploration only.

2. WHERE: filter rows

SELECT FirstName, Country, Score
FROM Customers
WHERE Country = 'USA';
FirstName | Country | Score Kevin | USA | 900 Mary | USA | 750 Anna | USA | NULL

WHERE keeps rows where the condition is true. (Full details in topic 7.)

3. ORDER BY: sort the result

SELECT FirstName, Score
FROM Customers
ORDER BY Score DESC;           -- highest first. ASC (lowest first) is the default
FirstName | Score Kevin | 900 Mary | 750 Mark | 500 Jossef | 350 Anna | NULL
NULLs and sortingSQL Server treats NULL as the smallest value: first in ASC, last in DESC. Other databases differ (PostgreSQL puts NULLs last in ASC).

Sort by several columns: the second column breaks ties of the first.

SELECT Country, FirstName, Score
FROM Customers
ORDER BY Country ASC, Score DESC;
Country | FirstName | Score Germany | Mark | 500 Germany | Jossef | 350 USA | Kevin | 900 USA | Mary | 750 USA | Anna | NULL

Without ORDER BY the row order is not guaranteed, even if it looks sorted today. Always sort when order matters.

4. GROUP BY: one row per group

SELECT Country, SUM(Score) AS TotalScore, COUNT(*) AS Customers
FROM Customers
GROUP BY Country;
Country | TotalScore | Customers Germany | 850 | 2 USA | 1650 | 3

Rule: every column in SELECT must be either in GROUP BY or inside an aggregate function (SUM, COUNT, AVG, MIN, MAX). Anna's NULL score is ignored by SUM, but she is still counted by COUNT(*). More in topic 17.

5. HAVING: filter groups

SELECT Country, SUM(Score) AS TotalScore
FROM Customers
GROUP BY Country
HAVING SUM(Score) > 1000;
Country | TotalScore USA | 1650
WHERE vs HAVINGWHERE filters rows before grouping, so it cannot use aggregates. HAVING filters groups after grouping, so it can.

6. DISTINCT: remove duplicate rows

SELECT DISTINCT Country FROM Customers;
Country Germany USA

DISTINCT applies to the whole row of selected columns, not just the first. It needs to sort or hash all rows, so do not sprinkle it on to "fix" duplicates you do not understand; usually a join is the real cause.

7. TOP and OFFSET-FETCH: limit rows

SELECT TOP 3 FirstName, Score FROM Customers ORDER BY Score DESC;   -- the 3 best
SELECT TOP 1 WITH TIES ...                                            -- includes rows tied with the last
SELECT TOP 20 PERCENT * FROM Customers;                               -- top fifth

-- pagination: skip 2, take 2 (ORDER BY is required)
SELECT FirstName, Score FROM Customers
ORDER BY Score DESC
OFFSET 2 ROWS FETCH NEXT 2 ROWS ONLY;
FirstName | Score Kevin | 900 Mary | 750 Mark | 500
FirstName | Score Mark | 500 Jossef | 350
TOP without ORDER BYreturns "some" rows, not the best rows. Always pair them.

MySQL/PostgreSQL write LIMIT 3 instead of TOP 3.

8. Aliases, static values, comments

SELECT
    CustomerID            AS Id,                       -- column alias
    FirstName + ' ' + LastName AS FullName,            -- expression (NULL if either is NULL!)
    'Customer'            AS Type,                     -- static value, same on every row
    Score * 2             AS DoubleScore
FROM Customers AS c;                                    -- table alias (short name)
-- single-line comment
/* multi-line
   comment */

Aliases rename things in the output or give short names. A column alias made in SELECT cannot be used in the same query's WHERE (reason below).

The order SQL really runs (logical processing order)

You write SELECT first, but the engine does not start there:

Run orderClauseWhat it does
1FROM / JOINFind the tables, build the starting rows
2WHEREDrop rows
3GROUP BYBucket rows
4HAVINGDrop buckets
5SELECT (incl. window functions, DISTINCT)Compute output columns
6ORDER BYSort
7TOP / OFFSET-FETCHCut

Common mistakes

  • Using an aggregate in WHERE: WHERE SUM(Score) > 100 fails. Use HAVING.
  • Selecting a non-grouped column: SELECT Country, FirstName ... GROUP BY Country fails.
  • Expecting order without ORDER BY.
  • FirstName + ' ' + LastName returns NULL for Mary. Fix with CONCAT or ISNULL (topic 12, 15).
