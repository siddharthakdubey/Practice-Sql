Window functions: basics

Calculate across related rows without collapsing them. The single most valuable SQL skill after joins.

After this topic you will read and write function() OVER (PARTITION BY ... ORDER BY ...), explain how it differs from GROUP BY, and know where window functions are allowed and when they run.

The problem GROUP BY cannot solve

"Show each employee and the total salary of their department next to them." With GROUP BY you get one row per department and lose the employees:

SELECT Department, SUM(Salary) AS DeptTotal
FROM Employees
GROUP BY Department;

To keep the people you would need a self-join or subquery. A window function does it directly:

SELECT EmployeeID, FirstName, Department, Salary,
       SUM(Salary) OVER (PARTITION BY Department) AS DeptTotal
FROM Employees;

Anatomy

function_name(arguments) OVER (
    PARTITION BY col1, col2     -- optional: split rows into independent groups ("windows")
    ORDER BY     col3 DESC      -- optional/required: order inside each partition
    ROWS BETWEEN ...            -- optional: which neighbouring rows to include (frame, topic 19)
)

Empty OVER(): the whole table is the window

SELECT FirstName, Salary,
       SUM(Salary) OVER ()                         AS CompanyTotal,    -- 340000 on every row
       ROUND(100.0 * Salary / SUM(Salary) OVER (), 2) AS PctOfCompany
FROM Employees;
FirstName | Salary | CompanyTotal | PctOfCompany Frank | 55000 | 340000 | 16.18 Kevin | 65000 | 340000 | 19.12 Mary | 75000 | 340000 | 22.06 Michael | 90000 | 340000 | 26.47 Carol | 55000 | 340000 | 16.18

A "percent of total" with no subquery or join: this single idiom justifies learning windows.

GROUP BY and window together

The window runs after GROUP BY, on the grouped rows. So you can window over aggregates:

SELECT CustomerID,
       SUM(Sales) AS Total,
       RANK() OVER (ORDER BY SUM(Sales) DESC) AS Rnk     -- rank the per-customer totals
FROM Orders
GROUP BY CustomerID;
CustomerID | Total | Rnk 6 | 90 | 1 4 | 85 | 2 2 | 65 | 3 1 | 60 | 4 3 | 60 | 4

Customers 1 and 3 tie at 60, so both get rank 4 (RANK leaves ties; topic 20).

Rules and limits

  • Allowed only in SELECT and ORDER BY. Not in WHERE, GROUP BY or HAVING, because it runs after them. To filter on a window result, wrap it in a CTE or subquery:
WITH ranked AS (
    SELECT FirstName, Department, Salary,
           ROW_NUMBER() OVER (PARTITION BY Department ORDER BY Salary DESC) AS rn
    FROM Employees
)
SELECT * FROM ranked WHERE rn = 1;        -- top earner per department
FirstName | Department | Salary | rn Kevin | Marketing | 65000 | 1 Michael | Sales | 90000 | 1
  • Window functions cannot be nested inside one another.
  • Each window function has its own OVER clause. If several use the same one, SQL Server 2022 lets you name it once with a WINDOW w AS (...) clause; older versions repeat the text.

Execution order (why you can't filter on them)

FROM/JOIN → WHERE → GROUP BY → HAVING → window functions → SELECT/DISTINCT → ORDER BY → TOP. Window functions see the rows after WHERE and GROUP BY have shrunk them. That is also why "rank only the Delivered orders" works by putting the filter in the same query's WHERE.
