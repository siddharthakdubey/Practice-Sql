Set operators

Joins add columns side by side. Set operators stack rows on top of each other: UNION, UNION ALL, EXCEPT, INTERSECT.

After this topic you will know the four set operators, the rules the two queries must follow, when UNION ALL beats UNION, and how to use EXCEPT/INTERSECT for comparing data sets.

Join vs set operator

JOINSet operator
Combines tables horizontally (more columns), matching rows by a keyCombines results vertically (more rows), matching whole rows
Customers + Orders on CustomerIDCustomers rows + Employees rows

The rules (all four operators)

  1. Both queries return the same number of columns.
  2. Columns are matched by position, not by name, and their data types must be compatible.
  3. The column names come from the first query.
  4. ORDER BY is allowed only once, at the very end, and applies to the combined result.
  5. Each side can have its own WHERE, GROUP BY, joins...

We will work with the first names: Customers = {Jossef, Kevin, Mary, Mark, Anna}; Employees = {Frank, Kevin, Mary, Michael, Carol}. Kevin and Mary appear in both.

UNION ALL: just stack them

SELECT FirstName FROM Customers
UNION ALL
SELECT FirstName FROM Employees;

10 rows (5 + 5), duplicates kept. Fastest: no extra work.

UNION: stack, then remove duplicates

SELECT FirstName FROM Customers
UNION
SELECT FirstName FROM Employees;
Default to UNION ALLUNION must sort or hash everything to find duplicates (slow on big data) and it also removes duplicates inside each side that you may want to keep. Use UNION only when you really need distinct rows. If you know the sets cannot overlap (e.g. 2024 table + 2025 table), UNION ALL is both right and faster.

EXCEPT: in the first, not in the second

SELECT FirstName FROM Customers
EXCEPT
SELECT FirstName FROM Employees;

Order matters: A EXCEPT B is not B EXCEPT A. Oracle calls this MINUS. EXCEPT also removes duplicates in its result.

INTERSECT: in both

SELECT FirstName FROM Customers
INTERSECT
SELECT FirstName FROM Employees;

NULL in set operatorsUnlike =, set operators treat two NULLs as equal when comparing rows. So (NULL) in both inputs is a "match" for INTERSECT and a duplicate for UNION.

Real-life uses

  • Combine similar tables: Orders_2024 UNION ALL Orders_2025 (and add a column saying which source).
  • Data migration check: SELECT * FROM Old EXCEPT SELECT * FROM New returns rows that failed to migrate. Run it both ways.
  • Stack different shapes: add a static label column so you know where each row came from:
SELECT 'Customer' AS Source, FirstName, LastName FROM Customers
UNION ALL
SELECT 'Employee',           FirstName, LastName FROM Employees
ORDER BY Source, FirstName;           -- ORDER BY only once, at the end
  • Report with subtotals: UNION ALL a detail query and a total query.
