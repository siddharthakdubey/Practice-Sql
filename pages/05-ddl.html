DDL commands

Data Definition Language: create, change and remove the structure that holds your data.

After this topic you will create tables with proper data types and constraints, alter and drop them, and know how DROP, TRUNCATE and DELETE differ.

CREATE TABLE

CREATE TABLE Persons (
    ID        INT           NOT NULL,
    Name      VARCHAR(50)   NOT NULL,
    BirthDate DATE          NULL,
    Phone     VARCHAR(15)   NULL,
    CONSTRAINT pk_persons PRIMARY KEY (ID)
);
  • Table name then a list of column definitions: name, data type, nullability.
  • NOT NULL: a value is required. NULL: may be missing.
  • CONSTRAINT pk_persons PRIMARY KEY (ID): a named rule. Name your constraints; error messages and later ALTERs become readable.

ALTER TABLE: change an existing table

ALTER TABLE Persons ADD Email VARCHAR(100) NULL;                 -- add a column
ALTER TABLE Persons ALTER COLUMN Phone VARCHAR(20) NULL;         -- change type / size
ALTER TABLE Persons DROP COLUMN Email;                           -- remove a column (data lost!)
ALTER TABLE Persons ADD CONSTRAINT ck_age CHECK (BirthDate > '1900-01-01');
ALTER TABLE Persons DROP CONSTRAINT ck_age;
EXEC sp_rename 'Persons.Phone', 'Mobile', 'COLUMN';              -- rename (T-SQL specific)
Adding a NOT NULL column to a table with rowsfails unless you give a DEFAULT, because existing rows would have no value. On big tables ALTER can lock the table: do it in a quiet window.

Good design basics

  • One fact in one place (normalisation): store a customer's country once in Customers, not in every order; link by key.
  • Every table gets a primary key.
  • Choose the narrowest correct type; use DECIMAL for money and DATE for dates, never text.
  • Let the database enforce rules (constraints) rather than trusting every application.
  • Name consistently: pk_, fk_, uq_, ck_, df_ prefixes.
Try it

1) Create a table Branches (BranchID identity PK, Name unique not null, OpenedOn date default today). 2) Insert a duplicate Name and read the error. 3) Add a column City. 4) Drop the table. Note the error numbers (2627 = unique violation).
