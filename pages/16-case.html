CASE statement

If / else logic inside a query: categorise rows, map codes to labels, and aggregate conditionally.

After this topic you will write searched and simple CASE, use it in SELECT, ORDER BY, GROUP BY, UPDATE and inside aggregates (conditional aggregation / manual pivot), and know its evaluation rules.

Searched CASE: conditions, first true wins

SELECT OrderID, Sales,
       CASE
           WHEN Sales >= 50 THEN 'High'
           WHEN Sales >= 30 THEN 'Medium'
           ELSE                  'Low'
       END AS Category
FROM Orders;
  • Conditions are tested top to bottom. The first true one returns its value and the rest are skipped. That is why the order matters: 60 is >= 50 and >= 30, but gets 'High'.
  • ELSE is the default. If you omit ELSE and nothing matches, the result is NULL.
  • END closes it. Give the result an alias.

Simple CASE: compare one value to many

SELECT OrderID,
       CASE OrderStatus
           WHEN 'Delivered'  THEN 'Done'
           WHEN 'Shipped'    THEN 'On the way'
           WHEN 'Processing' THEN 'Being packed'
           ELSE 'Unknown'
       END AS Friendly
FROM Orders;

Shorthand for CASE WHEN OrderStatus = 'Delivered' .... It can only test equality. For ranges, IS NULL or anything else, use the searched form. (Careful: a simple CASE cannot match NULL because it uses =.)

Rules to remember

  1. All THEN/ELSE results must be of compatible types: you cannot return text in one branch and a number in another (THEN 'High' ... ELSE 0 errors; use '0' or CAST).
  2. CASE is an expression, not a statement: it returns a value, usable anywhere an expression can go.
  3. Use IS NULL inside: WHEN ShipDate IS NULL THEN 'Not shipped'.
  4. Shorter two-way version: IIF(Sales >= 50, 'High', 'Low') (T-SQL).

Where CASE can go

In GROUP BY: group by the category

SELECT CASE WHEN Sales >= 50 THEN 'High' WHEN Sales >= 30 THEN 'Medium' ELSE 'Low' END AS Category,
       COUNT(*) AS Orders, SUM(Sales) AS Total
FROM Orders
GROUP BY CASE WHEN Sales >= 50 THEN 'High' WHEN Sales >= 30 THEN 'Medium' ELSE 'Low' END;
Category | Orders | Total High | 3 | 200 Medium | 3 | 125 Low | 4 | 75

You must repeat the CASE in GROUP BY (the alias does not exist yet at that stage; topic 4). Cleaner: put the CASE in a subquery or CTE first, then group by the alias (topic 24).

In ORDER BY: custom sort order

SELECT OrderID, OrderStatus FROM Orders
ORDER BY CASE OrderStatus WHEN 'Processing' THEN 1 WHEN 'Shipped' THEN 2 ELSE 3 END;   -- unfinished work first

In UPDATE: change by rule

UPDATE Employees
SET Salary = CASE WHEN Department = 'Sales' THEN Salary * 1.10
                  WHEN Department = 'Marketing' THEN Salary * 1.05
                  ELSE Salary END;           -- ELSE Salary = leave as is (otherwise NULL!)

Inside aggregates: conditional aggregation (the pivot trick)

SELECT SUM(CASE WHEN OrderStatus = 'Delivered'  THEN Sales ELSE 0 END) AS DeliveredSales,
       SUM(CASE WHEN OrderStatus = 'Shipped'    THEN Sales ELSE 0 END) AS ShippedSales,
       SUM(CASE WHEN OrderStatus = 'Processing' THEN Sales ELSE 0 END) AS ProcessingSales,
       COUNT(CASE WHEN ShipDate IS NULL THEN 1 END)                    AS NotShipped   -- COUNT ignores the NULLs
FROM Orders;
DeliveredSales | ShippedSales | ProcessingSales | NotShipped 190 | 170 | 40 | 1

One pass over the table gives several totals side by side, instead of GROUP BY's several rows. It is the portable way to build cross-tabs (T-SQL also has PIVOT). Another classic: a "flag" total, e.g. SUM(CASE WHEN Score > 500 THEN 1 ELSE 0 END) = how many customers score above 500.

Fixing data: replace bad codes

SELECT FirstName,
       CASE WHEN Score IS NULL THEN 'Unrated'
            WHEN Score >= 700    THEN 'Gold'
            WHEN Score >= 400    THEN 'Silver'
            ELSE 'Bronze' END AS Tier
FROM Customers;
FirstName | Tier Jossef | Bronze Kevin | Gold Mary | Gold Mark | Silver Anna | Unrated
Order your NULL check firstIf you test Score >= 700 before IS NULL nothing breaks here (NULL fails the test), but a final ELSE 'Bronze' would then label Anna "Bronze". Always decide where NULL goes.
