Learn SQL: Beginner to Advanced

34 topics, one small shared database, and a step-by-step visual for every concept where data moves (joins, GROUP BY, windows, CTEs, indexes...). Dialect: SQL Server (T-SQL).

How to use this course
  1. Run sql/00_setup.sql once in SSMS or Azure Data Studio. It creates the database MyDatabase with 4 tiny tables. Every example in the course uses these same tables, so you always know the data.
  2. Open a topic, read it, press Next ▶ in the visuals to watch the rows move, then run the example yourself.
  3. Do the "Try it" boxes. Typing the query yourself is where the learning happens.
  4. Tick Mark as completed at the bottom of each topic (saved in your browser).

The sample database

Small on purpose: you can hold all the rows in your head, so you can predict each result before you run it. It also has deliberate "dirty" spots: a customer with no orders (Anna), an order for a customer that does not exist (1004), NULLs in names, scores and ship dates, and a product nobody bought (Socks).

Phase 2: your 120-question practice plan

Once you finish reading, we link this folder to your Git repository and add a practice/ folder. My suggested structure (and a few upgrades to your plan):

  • 120 questions in 8 sets of 15, each set with its own small dataset (retail, HR, banking, e-commerce, hospital, airline, school, SaaS subscriptions) so you do not only learn one schema. Banking and finance sets will feel familiar from your job.
  • Difficulty ramp: Set 1-2 filtering, joins and aggregates; Set 3-4 window functions and CTEs; Set 5-6 subqueries, recursion, gaps-and-islands, running totals, deduplication; Set 7-8 performance, indexing, execution plans, stored procedures, triggers.
  • Every question has: business story, tables, expected output, a hint (hidden until you ask), and your answer file Q045.sql. I review the file, add remarks in Q045.review.md (correctness, readability, performance, a better alternative) and commit.
  • Extra ideas: (1) "spot the bug" questions with broken queries; (2) 3 mini case-studies at the end, each combining 5+ concepts; (3) a weekly 10-minute recap of the questions you got wrong; (4) a progress table in the README that I update on each push; (5) a "bank-style" set (ledger, reconciliation, interest accrual, SCD2 history) because that is where your day job lives.

Tip: one place to track your plan is the progress table I will generate in README.md.
